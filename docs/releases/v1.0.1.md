# v1.0.1 — Endpoint pruning on Node.js 20

On Windows with Node.js 20, the bridge could not read the list of local pipes: Node.js 20 refuses to list the pipe directory the way later versions do. As a result, records of closed Codex Desktop launches were never pruned there, and `bridge_doctor` counted every saved record as pointing to an existing endpoint. The bridge now reads that directory in a way that works on every supported Node.js version.

## Validation

- Final local Windows release validation passed 466 of 470 tests on Node.js 20 and on Node.js 26, with 4 macOS-specific tests skipped and no failures.
- Manifest alignment and package generation checks pass.

## Requirements and limitations

- Node.js 20 or later is required.
- The bridge cannot repair a stalled Codex Desktop; it can only identify one. Restarting Desktop is still required.
- Claude may hold or refuse inbound messages under its own policy. A transport receipt is not a model-read or completion receipt.

## Updating

Run `node scripts/install.mjs` again, or update the plugin through its marketplace. Coming from a version before 1.0.0, read the [1.0.0 update notes](v1.0.0.md#updating) first. Then load the new server: in Claude CLI, run `/reload-plugins` and check `/mcp`. Start a new Claude Code session in VS Code, and fully quit and reopen Claude Desktop. Start a new Codex Desktop task or restart the application, and restart terminal Codex sessions.
