# v1.0.0 — Claude–Codex Bridge, with stable names and clear Codex Desktop failures

The bridge works with Claude and Codex in their desktop apps and terminals, in any combination. Version 1.0.0 gives it names that say so: the plugin, its marketplace, several tools, its environment variables, and its state folder are renamed once, and from this release on these public names stay stable. The repository is now [KeeVeeG/claude-codex-bridge](https://github.com/KeeVeeG/claude-codex-bridge); old repository links redirect.

## Renamed

| Before | Now |
| --- | --- |
| plugin `codex-claude-desktop-bridge` | `bridge-claude-codex` |
| marketplace `keeveeg-desktop-bridge` | `keeveeg`, so the plugin installs as `bridge-claude-codex@keeveeg` |
| `list_codex_chats` | `list_codex_threads`, returning `threads` |
| `bridge_status` | `list_deliveries`, returning `deliveries`; registering a Codex Desktop task moved to `bridge_doctor` |
| state folder `~/.local/share/codex-claude-desktop-bridge` | `~/.local/share/claude-codex-bridge` |
| environment variables `CODEX_CLAUDE_BRIDGE_*` | `CLAUDE_CODEX_BRIDGE_*` |
| skill `claude-bridge` | `bridge` |

`list_claude_sessions`, `send_to_claude`, `send_to_codex`, `bridge_doctor`, `bridge_panel`, and their inputs keep their names. Outputs now use one style: `session_id` and `title` in Claude session lists, and a `delivery` object from both send tools and `list_deliveries`, without internal bookkeeping fields. Claude permission rules change with the plugin name: the send tool is now `mcp__plugin_bridge-claude-codex_bridge-claude-codex__send_to_codex`.

The project, its repository, archives, and state folder are named `claude-codex-bridge`. Only the plugin ID reads `bridge-claude-codex`, because Claude Code reserves third-party plugin IDs that start with `claude-`.

## Fixes for an unreachable Codex Desktop

When Claude could not reach Codex Desktop, the bridge used to report only the last endpoint it tried, usually one left over from an earlier Desktop launch. A running Desktop that accepted the connection but never answered was hidden behind "no longer exists", and the suggested `bridge_status` call did not register anything. This release reports each cause separately, prunes endpoints that are gone, and makes the suggested fix work: `bridge_doctor`, run once from an open Codex Desktop task, now registers it.

- **Per-cause errors:** when no registered Codex Desktop endpoint answers, the error names every cause found. A Desktop that is running but did not answer in time gets the advice to restart it. A rejected task context gets the advice to run `bridge_doctor` from an open Desktop task. Endpoints from earlier Desktop launches are counted, and they get their own advice only when they are the sole cause.
- **Registry pruning:** Codex Desktop creates a new app-tools pipe on every launch. Registering an endpoint now drops saved records whose pipe no longer exists. The check reads the Windows pipe directory and never connects to a pipe.
- **Bounded discovery:** each endpoint gets one catalog probe and at most one stalled listing, within an overall time budget. Records the budget leaves unchecked are reported as unchecked, not as a stalled Desktop.
- **`bridge_doctor` registers the task:** run from a Codex Desktop task, it registers that task's endpoint for discovery from Claude, as the error advice says. It sends nothing and changes no settings, and every list tool stays read-only.
- **Sends survive a stalled discovery:** `send_to_codex` reuses the task context accepted by the previous discovery and reads the app-tools catalog once per send. A stalled listing or `bridge_doctor` run keeps that context; only a rejection drops it.
- **Clearer diagnosis:** `bridge_doctor` reports how many saved records point to an existing endpoint, checks Desktop with shorter timeouts, and uses the same per-cause wording.
## Other changes

- **Descriptions for every client:** the plugin, catalog, skill, and server descriptions no longer read as Desktop-only. Diagnostics and the panel say "Claude Code session" instead of naming Desktop or CLI, which also left out VS Code.
- **Installer keeps one backup:** each install still backs up the previously staged plugin and the personal marketplace catalog, but now removes older backups of both after a successful install.
- **Installer tolerates a broken Codex catalog:** Codex refuses to list plugins while any configured marketplace is unreadable, even an unrelated one. The installer now finds old bridge registrations in Codex's own configuration instead, checks that each selected CLI starts, and finds everything before it removes anything.
- **Leaner repository:** the README is shortened to installation, usage, and troubleshooting, with details already owned by the publishing guide and the bridge skill moved out and stale notes removed. Superseded design notes, unused code paths, and hidden panel elements are gone.

## Requirements and limitations

- Node.js 20 or later is required.
- The bridge cannot repair a stalled Codex Desktop; it can only identify one. Restarting Desktop is still required.
- Claude may hold or refuse inbound messages under its own policy. A transport receipt is not a model-read or completion receipt.

## Updating

**With the included installer:** run `node scripts/install.mjs` as before. It removes the old `codex-claude-desktop-bridge` plugin and its catalogs from Claude and Codex, carries your Claude permission rules for the old tool names over to the new ones with their allow, ask, or deny choice intact, and moves the state folder with its delivery history. It refuses to run while an old `CODEX_CLAUDE_BRIDGE_*` variable is set and names its replacement. Codex can run during the update: while it holds the old plugin's files, the installer turns that plugin off in Codex's `config.toml` and keeps a backup; run the installer again after restarting Codex to delete the old files.

**From the Git marketplace:** remove the old plugin and catalog, then add the repository again:

```powershell
claude plugin uninstall codex-claude-desktop-bridge@keeveeg-desktop-bridge --scope user
claude plugin marketplace remove keeveeg-desktop-bridge
claude plugin marketplace add https://github.com/KeeVeeG/claude-codex-bridge.git
claude plugin install bridge-claude-codex@keeveeg --scope user
codex plugin remove codex-claude-desktop-bridge@keeveeg-desktop-bridge
codex plugin marketplace remove keeveeg-desktop-bridge
codex plugin marketplace add https://github.com/KeeVeeG/claude-codex-bridge.git
codex plugin add bridge-claude-codex@keeveeg
```

Re-create any Claude permission rules for the old tool names under the new prefix. The bridge moves the state folder itself on first start.

Then load the new server: in Claude CLI, run `/reload-plugins` and check `/mcp`; if old tools remain, exit and resume the exact session. Start a new Claude Code session in VS Code, and fully quit and reopen Claude Desktop. Start a new Codex Desktop task or restart the application, and restart terminal Codex sessions.
