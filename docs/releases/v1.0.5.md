# v1.0.5 — One conversation in two windows

When a Claude Code conversation ran in two processes at once, for example resumed with `claude --resume` in a new terminal while the old window still ran, the bridge refused every call from either window with "More than one process claims this Claude session". Now each window calls the bridge as itself, identified by its own process, and a message sent to that conversation goes to the window used last. A send already under way stays with the window it chose. Closing and reopening a conversation never needed this; it only shows when the old process keeps running.

## Validation

- Final local Windows release validation passed 467 of 471 tests on Node.js 20 and on Node.js 26, with 4 macOS-specific tests skipped and no failures.
- Manifest alignment and package generation checks pass.

## Requirements and limitations

- Node.js 20 or later is required.
- The bridge cannot repair a stalled Codex Desktop; it can only identify one. Restarting Desktop is still required.
- Claude may hold or refuse inbound messages under its own policy. A transport receipt is not a model-read or completion receipt.

## Updating

Run `node scripts/install.mjs` again, or update the plugin through its marketplace. Coming from a version before 1.0.0, read the [1.0.0 update notes](v1.0.0.md#updating) first. Then load the new server: in Claude CLI, run `/reload-plugins` and check `/mcp`; if it warns that the conversation would be re-read, run `/reload-plugins --force`. Start a new Claude Code session in VS Code, and fully quit and reopen Claude Desktop. Fully quit Codex Desktop, not only its window, and reopen it; restart terminal Codex sessions.
