# Bridge 1.1.0

Draft for release review.

## What changed

- **Delivery tells you what happened.** Send results distinguish a confirmed transport handoff, a confirmed no-write failure, and an unknown result, with a recovery step for each. An ordinary repeat reports the previous result; it does not write. To retry a **recorded, proven no-write** failure, set `retry_failed: true` with its original ID, route and text. Older failed records without a cause stay inspect-only. For an uncertain attempt, inspect the recipient and outgoing records; an absent message is not proof of non-delivery. If a reserved auto route unloads and needs an explicit transport, confirm Desktop or CLI and send under a fresh ID without the retry flag. `submitted` still means a transport write; it does not guarantee the recipient read or accepted the message. Peer notices separate verified sender identity from the quoted text.
- **Calls are bounded.** The 55-second tool budget includes time spent queued. This is not a deadline for the receiving conversation to reply. An overdue final identity check does not prove a recipient changed or went offline. Final daemon routing reads can retry within the remaining budget, without repeating a write; access denial stops the send instead of changing routes. The server refuses to start with `NODE_DEBUG=child_process` because that tracing can log private data; unset it before starting.
- **Discovery is more useful when part of a route is down.** A stale Codex Desktop record no longer hides another usable one. When a Claude conversation is open twice, the bridge chooses a reachable window by status activity. Spare and parked Claude processes and unusable daemon rows are omitted instead of looking sendable. A partially checked catalog can warn without losing the results it found. Transport errors and doctor checks give bridge-owned causes instead of raw upstream diagnostics.
- **Local delivery records stay in place.** The bridge no longer moves old state online. Reads can continue while a send waits for a ledger lock, and paged history can report a gap rather than silently skipping it. Existing receipts are retained; the [offline migration and rollback guidance](../../README.md#updating-from-a-version-before-100) matters if more than one state location exists.
- **The conversation panel handles interrupted sends better.** It keeps edits made during a send, shows the Claude handoff and the copy to your Codex chat separately, and names both destinations before sending. **Check again** reads history only; it never resubmits the draft. If Codex does not report its Enter setting, Enter adds a line and Ctrl+Enter or Cmd+Enter sends in the new panel. A replay or copy-only retry reports an unsaved primary receipt separately from the copy. A claimed or uncertain copy retry replaces an earlier refusal, and a conversation going offline disables its text retry until reopened. The panel offers a copy-only retry when safe. If the compatible notice ledger is full, the bridge deliberately omits the copy rather than risk a second post by an old writer. Saved conversation titles and project folders are in widget metadata instead of the model-visible launcher result.
- **Installing no longer creates a second Claude project server in the source checkout.** Claude MCP configuration belongs to the plugin. Local settings stay out of release packages, and the installer preserves unidentified directories and unmarked backups.

- **Shorter send receipts are opt-in.** `include_message: false` omits only your own text from a public send receipt. Old calls still receive the message, and ledger and panel records still include it. The short `summary` on public sends, exact-ID lookup and caller-specific doctor `diagnosis` are additive. To check an unclear handoff once, use `list_deliveries` with its `message_id` and match the exact route. An absent record does not establish whether the message went out; no native read receipt is implied.
- **Replies and troubleshooting:** use the verified conversation ID, not an incoming message ID. A Windows terminal-origin notice does not promise a usable return transport. Verify the return route, including its host when using SSH. Doctor can identify one observed blocker and its next action without prescribing repairs for unused routes.

## Compatibility and updating

- **Route changes:** Windows Codex Desktop sends are local only; a Desktop without a host-aware send tool can still list its local chats with a warning, but cannot take a send. The outbound Codex route on macOS requires an explicit SSH alias and never falls back locally. Only loaded idle SSH targets are listed. SSH connection sharing is disabled. The merged SSH route is covered by simulated transport tests, not a new live smoke test.
- **If panel and server versions differ:** a cached 1.0.6 panel can still work with a 1.1 server but lists live conversations only, with fixed, non-identifying catalog warnings still available in the launcher response. The v6 picker does not display those warnings. This is a deliberate privacy correction, not full compatibility for legacy launcher consumers. The cached v6 panel retains its old Enter/modifier hint; follow the hint in the loaded panel. The new panel reads the full saved catalog from the new server's widget metadata; with a 1.0.6 server it can read the catalog from the legacy result, without the new server's privacy boundary. The mixed versions were checked with host fixtures, not both native client combinations.
- **Paging across versions:** unchanged calls and v1 cursors use the 1.0 civil-time order. The updated panel opts into commit order when offered; v2 cursors cannot continue on a 1.0 server. Restart that view without a cursor on downgrade. A page with `incomplete: true` keeps its cursor for retry, including when the state folder disappears between pages or a damaged key points to a message for the selected pair. A live older writer is not abandoned because the system clock moved back or its copy claim retained a newer writer’s token.
- **Update both clients:** use the [installation and reload steps](../../README.md#installation), then check that each client is running the updated server. Restart non-interactive and desktop sessions as documented. A 1.0.6 server running from an unchanged client cache cannot see a newer install in a different folder: no warning there is not proof that it updated. Existing saved receipts are not a reason to resend anything after an update.
- **Updating 1.0.0–1.0.2 with the installer:** fully quit Claude and Codex, including terminal sessions, before running it; those servers load code from the folder the installer replaces. If you are not sure which version or source you have, quit them first as well.
- **Turned-off Codex bridge:** the installer stops before changing either client because the native Codex update would turn the bridge on. Use `--claude` to update Claude alone. When you want the bridge on again, enable it in Codex and rerun the installer. If you update through a Codex marketplace, turn it off again afterwards to keep it disabled.
- **Other update safeguards:** a failed installer update does not remove a registration you already had and returns each client to the version it ran before; when it cannot, it names each client's version and where to recover the previous one. An installer lock left by a stopped installer is named with the installer's own recovery step, not the state recovery. If Codex cannot read its configuration, a Codex cache holds edits the installer cannot verify, or another source has the bridge enabled, the installer stops and names the safe next step. Copy any newer or edited stage backups aside before running a 1.0.x installer for recovery: it removes stage backups by name. Use one source per client and back up cache edits before a marketplace update.
