# v1.0.2 — Clearer daemon status and update steps

- When no Codex daemon is running, the bridge now says so plainly instead of passing on the operating system's connection error, which on Windows read as a network failure. A Codex Desktop listing no longer repeats this warning every time; `bridge_doctor` still reports it.
- The update steps now cover Claude CLI holding a plugin reload: when `/reload-plugins` warns that the conversation would be re-read, the old server keeps running until `/reload-plugins --force`. Updating from 0.4.x always needs `--force`, because the 1.0.0 tool names changed.

## Validation

- Final local Windows release validation passed 467 of 471 tests on Node.js 20 and on Node.js 26, with 4 macOS-specific tests skipped and no failures.
- Manifest alignment and package generation checks pass.

## Requirements and limitations

- Node.js 20 or later is required.
- The bridge cannot repair a stalled Codex Desktop; it can only identify one. Restarting Desktop is still required.
- Claude may hold or refuse inbound messages under its own policy. A transport receipt is not a model-read or completion receipt.

## Updating

Run `node scripts/install.mjs` again, or update the plugin through its marketplace. Coming from a version before 1.0.0, read the [1.0.0 update notes](v1.0.0.md#updating) first. Then load the new server: in Claude CLI, run `/reload-plugins` and check `/mcp`; if it warns that the conversation would be re-read, run `/reload-plugins --force`. Start a new Claude Code session in VS Code, and fully quit and reopen Claude Desktop. Start a new Codex Desktop task or restart the application, and restart terminal Codex sessions.
